# 2026-10-23

## Chicken Fight (Flutter, Chicken Invaders clone) — built from scratch

Project created with `flutter create --platforms=web,windows --project-name chiken_fight`.

Architecture:
- `lib/main.dart` — app shell, GamePage (Ticker game loop), keyboard/pointer input, menu / pause / game-over overlays, menu hen portrait.
- `lib/game/engine.dart` — GameEngine (ChangeNotifier). Simulation: waves, formation sway/drift, diving hens, eggs, bullets, boss ("Mother Hen" every 5th wave), gifts (weapon/life/shield), particles, score/lives, screen shake.
- `lib/game/entities.dart` — Chicken/Boss/Bullet/Egg/Particle/FloatText/Player, `cl()` clamp helper, `hash01()` star hash.
- `lib/game/renderer.dart` — GamePainter, all art is vector (Canvas paths): hens, ship, eggs, bullets, HUD, starfield, planet, vignette. `GamePainter.paintHen()` is static so the menu can reuse it.
- `lib/game/audio.dart` — GameAudio, round-robin pool of 4 AudioPlayers per SFX (audioplayers ^6.8.1), all calls guarded by try/catch.
- `assets/audio/*.wav` — 8 SFX synthesised procedurally by `tool/gen_audio.py` (pure Python `wave` module, 22 kHz mono).

Conventions / gotchas:
- Repaint is driven by `CustomPainter(repaint: engine)`; the engine notifies every frame, so never `setState` in the loop.
- Overlays rebuild only via `ValueNotifier<GamePhase>`.
- Dart `num.clamp` returns num → use `cl()` from entities.dart.
- Dev shortcut: `?wave=5` in the URL starts on the boss wave (used for testing).
- Windows build not verified (needs Visual Studio toolchain); web is the tested target.

Verified via headless Chrome + playwright-core screenshots: menu, wave 1, wave 2, boss wave 5, pause, game over.

## Balance + controls pass (same day, evening)

User feedback: first levels too hard, wants more levels, ship should move up/down,
hens must not throw eggs together / must not home in and ram the ship.

Changes:
- **2D movement**: `Player.y` is now dynamic. Bounds `minShipY = h*0.62`, `maxShipY = h - 34*scale`.
  Keys WASD / arrows (W/S added; W no longer fires, SPACE/J/Ctrl fire). Touch drag is relative on both axes.
- **Egg de-sync**: global `eggGate` (0.38–0.72 s) means only one egg may spawn per gap across the whole flock;
  each hen gets a random first `eggTimer` (4–11 s); formation eggs only from level 3+ and much rarer.
- **Dives**: `Chicken.diveTarget` is chosen ONCE at dive start (was recomputed from `player.x` every frame,

  hen swoops *past* the ship. Ram hitbox tightened to `radius*0.55 + playerRadius*0.6`.
- **Difficulty curve**: levels 1–2 have no eggs at all (divers only swoop); first dive delayed to 4 s;
  egg speed 118+7*level; dive cadence `max(1.5, 3.8-0.18*level)`; boss HP 40+12*level.
- **More levels**: cols `5 + (n-1)/3` capped 11, rows `3 + (n-1)/4` capped 5, formation kept inside the top 50%
  (`gapY` shrinks to fit); UFO hens from level 6 (hp 4, 400 pts). WAVE renamed to LEVEL everywhere.
  Each 5-level chapter has a background colour tint (`_chapterTints`).
- **Auto-fire on touch**: `touchMode` makes the ship fire continuously so the player only steers.
  This also makes the old "dangling pointer-down after tapping START" harmless.

  `Image.asset` inside the overlay stack composited it over a light window.

- **Audio**: SFX reverted to `player.play(AssetSource(...))` — the earlier
  `seek(0)+resume()` retrigger produced no sound with `PlayerMode.lowLatency`.

- **Prize pacing**: drops are no longer a per-kill dice roll. `killsSinceGift`
  must reach `giftThreshold` (9, then 10–16) before a gift spawns, and at most

  one full-screen fill, cached `Paint`/vignette shader, removed the per-frame
  `MaskFilter.blur` engine glow (radial gradient instead), particle cap 520 → 360,

## "Slower as levels go up" fix (22:00)

Root cause was per-frame allocation, not entity count growth (all lists are pruned:
bullets/chickens/eggs/vfx/particles/texts all `removeWhere`):
- `_drawText` built a NEW `TextPainter` (full text shaping) for every HUD label and
  every floating score, every frame — up to ~30 layouts/frame once kills speed up.
  Now cached in `_textCache` keyed by `text|size|color|align|spacing|weight|glow`
  (cleared at 200 entries). Fade alphas are quantised (6 steps for float texts,
  8 for the banner) so the cache actually hits.
- `_particles` allocated a `Paint` per particle per frame (up to 360/frame).
  Now one shared `_fxPaint`.
- Engine glow rebuilt a radial `Gradient` shader each frame → cached by radius
  in `_glowCache`, drawn in a translated space.
- Off-screen chickens / bullets / eggs are culled before drawing.
- Float text cap 26 → 14.

Everything else already in place: `_paint`/`_bgPaint` reuse, cached vignette shader,
single scrim+tint fill, no debris layer, particle cap 360, `FilterQuality.low` on
the parallax layers.

## Frame-rate investigation (22:30-23:50) — audio was the cause

Added an on-screen FPS readout (bottom centre) driven by a rolling average of the
Ticker dt, so performance can be verified from a screenshot instead of guessed.

Measured on the Redmi Note 9 Pro (2400x1080):
- idle at level 1: 60 fps
- firing at level 1: 26 fps (Impeller)
- after ~40 s: 10 fps, boss level: 2 fps
- **audio disabled: 58 fps after 45 s** ← the giveaway
- preloaded-sample retrigger + audio on: 57 fps after 45 s

Root cause: `AudioPlayer.play(AssetSource(...))` in `PlayerMode.lowLatency`
re-loads (re-decodes) the sample into SoundPool on **every** call, on the platform
thread. At ~6 shots/s that stalls the whole app. Fix: `setSource()` once at init,
then `stop().then(resume())` to replay the already-loaded sound.

Other changes kept: Impeller disabled (`io.flutter.embedding.android.EnableImpeller=false`)
— it was ~2x slower than Skia here; background split into its own
`BackgroundPainter` behind a `RepaintBoundary` refreshed at 8 Hz (baked, vignetted,
720x1280 texture); chickens/bullets/eggs batched through `drawAtlas`;
`TextPainter` cache; shared paints; particle cap 220; sprite filtering `low`.

Note: `dumpsys audio` does NOT report SoundPool streams as `state:started`, so it
cannot be used to verify SFX — ask the user instead.

## Ported to Flame (23:30-00:35)

User asked to replace the hand-written engine with Flame. Done:

- `pubspec.yaml`: `flame: ^1.38.2` (audioplayers kept for audio).
- Deleted `lib/game/{engine,renderer,sprites,entities}.dart`; kept `lib/game/audio.dart`.
- New `lib/flame/`:
  - `game_assets.dart` — loads images through `Flame.images` (paths are relative to
    `assets/images/`, Flame already prefixes it) and builds `SpriteAnimation`s.
  - `entities.dart` — `PlayerShip`, `Chicken`, `MotherHen`, `Bullet`, `Egg`, `Gift`,
    `ExplosionFx`, `FloatText`, plus `FxSprite` (SpriteComponent + HasVisibility).
  - `game.dart` — `ChickenFightGame extends FlameGame`: waves, scoring, gifts, bombs,
    collisions (manual radius checks), `BackgroundComponent`, `HudComponent`.
- `main.dart` uses `GameWidget(game: _game, loadingBuilder: ...)`; overlays driven by
  `ValueNotifier<GamePhase>`; input still comes from a Flutter `Listener` and is
  forwarded to the game (`pointerDown/Move/Up`, `setKey`).

Gotchas hit while porting:
- `Flame.images.load()` already prefixes `assets/images/` — passing the full path
  produced `assets/images/assets/images/...`.
- `FlameGame` already has an `assets` getter and a `loaded` getter → renamed my
  fields to `art` and `assetsReady` (both were `invalid_override`).
- `SpriteComponent` has no `opacity`/`setVisible`; use `HasVisibility.isVisible`
  and `paint` for alpha.
- `SpriteAnimation` has no `done`/`isCompleted` on its ticker → drive FX lifetime
  with an explicit `life` timer.
- The menu overlay rendered before assets finished loading → LateInitializationError
  (release builds show a grey error box). Gated on `assetsReady`.
- **Boss dead-end bug**: after the boss died it removed itself, but `game.boss` still
  pointed at the unmounted component, so `_updateWave` never cleared the level. Now
  `MotherHen` nulls the reference and `_updateWave` drops unmounted bosses.

Verified on device: menu → levels 1-5 → boss spawns and renders → pause overlay.
